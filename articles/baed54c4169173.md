# 【大和機巧場】開発日報（2026年8月19日）

本日は「八百万駆動（ヤオヨロズエンジン）」のゲームUI制作を効率化するため、Blender 5.1.2上で動作する専用UI制作アドオン **「八百万 UI Collection Builder」** の開発を進めました。

これまでBevy側のRustコードへ直接UIの位置やサイズを書き込んでいましたが、MMOではタイトル画面だけでなく、キャラクター選択、HUD、インベントリ、クエスト、設定画面など多数のUI画面が必要になります。

そこで今回は、Blenderを単なる3Dモデル制作ツールとしてではなく、八百万駆動のUIを視覚的に組み立てるためのエディターとして利用する仕組みを試作しました。

---

## 1. 本日の主な開発トピック

### ① Blender 5.1.2向け「八百万 UI Collection Builder」の試作

最初にv0.1を作成し、Blender 5.1.2へ実際にインストールして動作確認を行いました。

基本設計では、ゲーム内の各UI画面をBlenderのCollectionとして管理します。

例：

- `SCR_Title`
- `SCR_CharacterSelection`
- `SCR_Gameplay`
- `SCR_Inventory`
- `SCR_Settings`

UIパーツについても用途ごとに命名規則を設定しました。

- `IMG_`：画像
- `BTN_`：ボタン
- `TXT_`：テキスト
- `CNT_`：コンテナ
- `ICO_`：アイコン

これにより、BlenderのOutlinerをそのままゲームUIの階層管理として利用できます。

---

### ② タイトル専用ではなく「画面コレクション方式」へ

当初は現在制作中のタイトル画面を視覚的に編集する用途から検討を始めました。

しかしMMOでは、タイトル画面だけでも開発は終わりません。

ゲームプレイ中には、

- HUD
- インベントリ
- スキル
- クエスト
- ギルド
- クラフト
- マップ
- ゲームメニュー

など、多数のUI画面が必要になります。

そこで「タイトル画面エディター」ではなく、複数のゲーム画面をCollection単位で作成・管理できる仕組みに変更しました。

また、Bevy側の `GameFlowState` とUI画面そのものは分離して扱います。

例えば `Gameplay` 状態の中でも、

`HUD / Inventory / Quest / Skill`

といった複数のUI画面を持てる設計です。

---

### ③ v0.1をBlender 5.1.2で実機テスト

作成したv0.1をBlender 5.1.2へインストールし、実際に操作しました。

画面Collectionの作成や、

- Image
- Button
- Text
- Container
- Icon

といったUI要素の生成が正常に動作することを確認しました。

Blender上にキャンバスを作り、その中へ矩形としてUIパーツを配置できるため、Rustコードへ座標を直接記述するよりも視覚的にレイアウトを考えられそうです。

一方、実際に操作してみると、UIの一部が英語、一部が日本語になっており、普段使いの制作ツールとしては少し分かりにくい点も見つかりました。

そこで、その場でv0.2への改修を行いました。

---

### ④ v0.2で日本語UIと視覚編集機能を強化

v0.2では、Blender上で表示される操作項目を基本的に日本語化しました。

ただし、ゲーム内部で利用するIDや命名規則については英語を維持します。

例えば、

- 表示名：`インベントリ`
- 画面ID：`Inventory`
- Collection：`SCR_Inventory`

というように、人間が読む名前とゲーム側で扱うIDを分離しました。

これにより、制作時には日本語で分かりやすく操作しながら、Rust/Bevy側では安定した英数字IDを利用できます。

さらにv0.2では以下の機能を追加しました。

- 画面Collectionの複製
- 画面ID変更時のCollection名追従
- 選択中の画面だけを表示
- UIキャンバスの中央表示
- PNG画像のプレビュー
- 八百万プロジェクトの `assets` フォルダ指定
- ピクセル単位の位置・サイズ表示
- 8px等のグリッドスナップ
- ContainerによるUIパーツの親子化
- UIデータのJSON書き出し
- ボタンAction設定
- `GameFlowState`との紐付け

---

### ⑤ BlenderからBevyへ渡すUIデータ構造を検討

UI Builderでは、BlenderからRustコードそのものを直接生成するのではなく、中間データとしてJSONを書き出す方式を採用しました。

想定している制作フローは次の通りです。

```text
Affinity Designer
        ↓
UI素材（PNG）

Blender
八百万 UI Collection Builder
        ↓
画面レイアウト
        ↓

        ↓
Bevy UI Loader
        ↓
