# はじめに

制作ノート、仕様書、TODO、開発ログ、Git操作。

開発していると、必要なものがどんどん増えていきます。

普段は既存のエディタを使えば十分なのですが、私の場合はゲーム開発やBlenderアドオン、配信ソフトなど、複数の制作物を並行して触ることが多く、

> 「自分の作業に必要な機能だけを、軽くまとめたエディタが欲しい」

と思うようになりました。

そこで作り始めたのが、Rust製の自作エディタ **「綴（つづり）」** です。

最初は「JSONで管理しているタスクを一覧表示して実行できればいい」くらいの小さなツールでした。

ところが作っているうちに、

- ファイルを開きたい
- 複数タブで編集したい
- Gitの変更を見たい
- Stage / Commitしたい
- Diffも見たい
- ファイル検索したい
- 検索・置換も欲しい
- コマンドパレットも欲しい

となり、気づけばかなりエディタらしくなってきました。

この記事では、**v0.2系のTask Runnerからv0.4.0まで、綴がどう育ってきたか**をまとめます。

---

# 綴とは

綴は、Rust + egui/eframeで作っている軽量エディタです。

目標は「VS CodeやZedを全部再実装する」ことではありません。

自分の制作環境に必要なものを絞って、

- 起動が軽い
- 日本語UI
- タスク実行
- ファイル編集
- Git操作
- 制作ノート管理

をひとつの画面にまとめることを目指しています。

現在の画面構成はだいたい次のようになっています。

```text
┌ Explorer / Tasks / Git ┬ Editor ───────────────┐
│                         │                        │
│                         │                        │
│                         │                        │
├─────────────────────────┴────────────────────────┤
│ Task Log / Git Log                              │
└──────────────────────────────────────────────────┘
```

かなり王道の構成ですが、使い慣れた形は強いです。

---

# v0.2系：最初はTask Runnerだった

綴の最初の役割は、JSONで分割したタスクを読み込んで実行することでした。

制作中は、

- Rustのテスト
- ビルド
- ファイル生成
- 補助スクリプト
- 独自タスク

などを何度も実行します。

それを毎回ターミナルに打つ代わりに、JSONへタスクを書いて一覧から呼び出せるようにしました。

ここで最初に遭遇したのが、GUIらしい問題です。

## ScrollAreaのID衝突

左右のパネルでスクロール領域を作ったところ、同じIDが使われて衝突しました。

そこで、

```text
task_list_scroll
task_log_scroll
```

のように、明示的に別IDを付けるように修正しました。

小さな問題ですが、eguiではこういうID管理が地味に重要でした。

## Windowsの実行ファイルロック

さらに、綴を起動したまま `cargo test` を実行すると、Windows側で実行中のexeがロックされる問題にも遭遇しました。

テスト時だけ出力先を分けることで回避しています。

```text
CARGO_TARGET_DIR=target/task-runner-test
```

このあたりから、

> 「単にボタンを置くだけではなく、開発ツールとして実際に使える必要がある」

という方向へ進み始めました。

# Gitをエディタ内へ

綴でかなり力を入れた部分がGitです。

最初はRustのGitライブラリを使うことも考えましたが、導入初期は安定性と確認のしやすさを優先して、ローカルの `git` コマンドを呼び出しています。

現在は次の操作ができます。

- 現在のブランチ表示
- `git status`
- Stage
- Unstage
- Stage All
- Unstage All
- Commit
- Pull
- Push
- Recent commits表示

Gitパネルでは、

```text
Staged Changes
Changes
```

を分けて表示しています。

さらに状態も、

```text
Modified
Added
Untracked
Deleted
Renamed
```

のように、人間が読みやすい形へ変換しました。

---

# Git Diffも中央で確認できるようにした

Gitパネルで変更ファイルをクリックすると、中央エリアでDiffを確認できます。

Staged側は、

```bash
git diff --cached
```

Changes側は通常の、

```bash
git diff
```

を使用しています。

その後、Diff表示も少しずつ改善しました。

- 追加行を色分け
- 削除行を色分け
- hunk見出しを色分け
- 旧行番号
- 新行番号
- Diffヘッダー表示

結果、エディタ内で

```text
編集 → Diff確認 → Stage → Commit
```

まで繋がるようになりました。

個人的には、このあたりからかなり「綴を綴自身の開発に使える」感じが出てきました。

---

# WindowsのLF / CRLF問題にも遭遇

Gitを触っていると、Windowsではおなじみの警告にも遭遇しました。

```text
LF will be replaced by CRLF
```

そこで `.gitattributes` を追加し、RustやMarkdown、JSON、TOMLなどの開発用テキストはLFへ寄せる方針にしました。

必要に応じて、

```bash
git add --renormalize .
```

で既存ファイルも揃えます。

地味ですが、こういう環境差を早めに潰しておくと後がかなり楽です。

---

# 複数ファイルタブと未保存保護

エディタとして使うなら、複数ファイルを開けないと始まりません。

そこで複数タブを追加しました。

- 複数ファイルを同時に開く
- 同じファイルなら既存タブへ移動
- 未保存タブに印を付ける
- タブを閉じる
- `Ctrl+S` で保存
- `Ctrl+W` でタブを閉じる

未保存ファイルを閉じようとした場合は、

```text
保存して閉じる
保存せず閉じる
キャンセル
```

の確認を表示します。

個人用ツールでも、ここはかなり重要です。

「間違えて閉じたら消えた」は一度でも起きると使わなくなるので、早い段階で保護を入れました。

---

# Explorerからファイル操作

Explorerも閲覧専用ではなく、操作できるようにしています。

現在は、

- 新規ファイル
- 新規フォルダ
- Rename
- Delete
- 右クリックメニュー

まで対応しました。

さらに、

- 新規ファイル作成後に自動で開く
- Rename後に開いているタブのパスを追従
- 未保存ファイルを含む削除は拒否
- Enterで実行
- Escでキャンセル
- ダイアログ表示時に入力欄へフォーカス

など、細かい操作性も少しずつ整えています。

こういう機能は1つ1つは小さいのですが、積み重なると一気に「普段使える感」が出ます。

---

# Ctrl+Pでファイルを開く

v0.3.9では、ファイル検索を追加しました。

```text
Ctrl + P
```

で「ファイルを開く」パレットを表示できます。

検索対象からは、

```text
.git
target
```

などの巨大ディレクトリを除外しています。

検索は大文字小文字を区別しない部分一致で、

- ↑↓で候補移動
- Enterで開く
- Escで閉じる

という操作です。

さらに検索語が空の場合は、最近開いたファイルを優先表示するようにしています。

ファイル数が増えてくるとExplorerを辿るより圧倒的に速いです。

---

# Ctrl+F / Ctrl+Hで検索・置換

同じv0.3.9で、エディタ内検索も追加しました。

```text
Ctrl + F
```

で検索、

```text
Ctrl + H
```

で検索＋置換です。

現在は、

- 一致件数表示
- 次へ
- 1件置換
- すべて置換

に対応しています。

ステータスバーには、

```text
Ln / Col
LF / CRLF
UTF-8
```

も表示しています。

まだシンタックスハイライトなどはありませんが、「文章やコードを触る最低限のエディタ」としてはかなり揃ってきました。

---

# v0.4.0：コマンドパレットを追加

そして現在の最新版が **v0.4.0** です。

ここで、

```text
Ctrl + Shift + P
```

のコマンドパレットを追加しました。

現在呼び出せる操作は、

- ファイルを開く
- 検索
- 置換
- 新規ファイル
- 新規フォルダ
- 保存
- タブを閉じる
- Explorerへ切り替え
- Tasksへ切り替え
- Gitへ切り替え
- Git状態更新

などです。

また、タブのドラッグ＆ドロップ並べ替えにも対応しました。

これでかなり「エディタとしての基本操作」が揃ってきた感があります。

# 作ってみて分かったこと

自作エディタは「テキストを編集できれば完成」ではありませんでした。

むしろ大変なのは、その周辺です。

- 未保存状態
- ファイル操作
- Git
- キーボードショートカット
- ウィンドウレイアウト
- スクロール
- Windows固有の挙動
- 改行コード
- フォーカス管理

こういう「普段は既存エディタが全部やってくれている部分」が大量にあります。

逆に言えば、それを1つずつ実装していくと、

> 「普段使っているエディタ、すごいな」

という気持ちになります。

同時に、自分に必要なものだけを自分の順番で育てられるのはかなり楽しいです。

# まとめ

最初は小さなTask Runnerだった綴ですが、

```text
Task Runner
↓
Explorer
↓
Editor
↓
Git
↓
Diff
↓
複数タブ
↓
ファイル操作
↓
```

と、少しずつ育ってきました。

一気に全部作ろうとすると大変ですが、

> 「今日使って不便だったところを、次のバージョンで1つ直す」

という進め方だと、意外と前に進めます。

まだv0.4.0ですが、自分自身の開発で使いながら育てられるところまで来ました。

Rust + eguiで自作エディタを作ってみたい人の参考になれば嬉しいです。

次は、エディタ本体の表示や補完まわりをもう少し深掘りしていく予定です。
