# はじめに

Rustで開発している軽量配信・録画ソフト **「燕 / Tsubame」** が、ひとまず GitHub で公開できるところまで進みました。

今回の記事では、ここまでに実装した機能、UIの整理、配布準備、GitHub Release、ライセンス対応、そして実際にゲームを使って行った負荷テストまでを一度まとめます。

まだ **Alpha版** ですが、単なる試作品ではなく、実際に配信・録画へ使えるところまで来ました。

GitHub:

https://github.com/mayu260112hakuhi-collab/tsubame-stream

---

# 燕 / Tsubame とは

燕は、Windows向けの配信・録画ソフトです。

開発で特に重視しているのは次の3点です。

- 軽量
- 安定
- 分かりやすいUI

OBSのような多機能配信ソフトをそのまま再現するのではなく、ゲーム配信や作業配信で必要な機能を整理しながら、できるだけ配信中の負荷を抑える方向で作っています。

技術構成は主に以下です。

- Rust
- eframe / egui
- Windows Graphics Capture
- WASAPI
- FFmpeg
- Windows 11

# UIの整理

かなり時間をかけたのがオーディオミキサーです。

最初は縦型ミキサーの幅や高さが揃わず、スライダーやメーターがずれたり、Masterだけ高さが違ったりしていました。

最終的には、

- PC音声
- マイク
- Master
- アプリ音声

をすべて同じ幅・同じ高さのチャンネルストリップとして揃える形にしました。

MasterにもMute / Mix / WAVの行を配置し、使えないものは無効表示にすることで、各チャンネルの位置がずれないようにしています。

また、Windowsの既定デバイスを使っている場合は、長いデバイス名ではなく `Win規定` と表示するようにして、UIが崩れにくいようにしました。

この段階でミキサーUIは一度固定し、次の開発へ進んでいます。

# Addon API v1

燕では、コア機能と拡張機能を分ける方向で設計しています。

コア側に置くのは、

- キャプチャ
- 配信
- 録画
- 音声

などの基本機能です。

追加機能は、今後アドオンとして分離していく予定です。

設定画面には現在、

- 通常設定
- 公式アドオン
- 外部アドオン

という構成があります。

Addon APIについては、OBSのように本体更新で外部プラグインが壊れやすくならないよう、できるだけ安定した境界を保つ方針です。

現在は **Addon API v1** の管理・登録基盤まで実装しています。

# ゲームを使った負荷テスト

ここからが今回かなり面白かった部分です。

実際にゲームを動かしながら、録画・配信時のCPU使用率を見ました。

## ゼンレスゾーンゼロ

録画時の燕は、

- プレビューあり: 約5%前後
- プレビューなし: 約2.3%前後

まで下がりました。

プレビューを閉じた時にかなり負荷が下がるので、以前入れた「プレビューOFF時は処理を抑える」最適化が効いていることが確認できました。

OBSも同じように確認すると、録画時は2%台前半程度で、燕とかなり近い値になりました。

録画だけでは差が小さく、ゼンゼロは比較対象としては少し分かりにくい印象でした。

---

# 原神で配信テスト

次に原神で配信テストをしました。

録画だけでなく、配信時の負荷を見るためです。

燕では、配信＋録画時でだいたい、

- CPU: 約4〜5%
- RAM: 約300MB前後
- Preview Drop: 0

程度でした。

さらにバトル中でも、燕は手元環境では **最大約6%程度** でした。

一方、OBSでは配信時にCPU使用率がかなり上がり、通常時でも10%台、バトル中に一時的に **47%程度** まで上がる場面がありました。

もちろん、この比較は完全なベンチマークではありません。

公開時には必ず、

> 同一PC・同一ゲーム環境での手元検証。設定や環境により結果は変動します。

という注記を付ける予定です。

また、今後は、

- 同じ解像度
- 同じFPS
- 同じビットレート
- 同じエンコーダー
- 同じゲームシーン

に揃えて、より厳密に比較する予定です。

---

# 配信時に重くないのは大きい

燕を作り始めた時から、一番重視していたのは、

**「配信ソフトがゲームの邪魔をしないこと」**

でした。

録画だけ軽くても、実際の配信で重くなるなら意味がありません。

今回、原神の配信＋録画時でもCPU使用率が低く抑えられたことで、少なくとも現時点の実装方針はかなり良い方向に進んでいることが確認できました。

これは今回の開発でかなり大きな成果だと思っています。

---

# プレビューOFFの効果

燕では、プレビューを閉じた時に不要なCPU側のプレビュー処理を減らしています。

その結果、ゲーム録画中でもCPU使用率が大きく下がりました。

実際の使い方としては、

1. 配信前にプレビューで確認
2. 問題なければプレビューを閉じる
3. そのまま配信・録画

という運用がかなり相性が良さそうです。

配信中ずっとプレビューを見る必要がない人にとっては、特に有効だと思います。

---

# Capture FPSについて

燕の画面には `Capture FPS` という表示があります。

ただし、これは完成した録画ファイルの実FPSと完全に同じ意味ではありません。

Windows Graphics Captureからフレームを受け取った頻度に近い値として使っているため、50fps台を表示していても、それだけで録画ファイルが50fpsになっているとは判断できません。

最終確認は、

- 録画ファイル
- 配信アーカイブ
- 実際のカクつき
- 音ズレ

を見て判断しています。

今後は、

- Capture FPS
- Preview FPS
- Encode FPS
- Output FPS
- Drop
- Duplicate frame
- Bitrate

のように、表示を分けた方が分かりやすいと考えています。

# 今後の予定

次は **Phase 10.3.0** として、配布後にユーザーが困りやすい部分を整えていく予定です。

主に、

- FFmpeg未検出
- 配信キー未設定
- 音声デバイス切断
- キャプチャ対象なし
- 配信設定エラー
- 初期診断
- 分かりやすいエラー表示

などです。

単にエラーを出すのではなく、

**「何が起きたか」**
**「何を直せばいいか」**

まで分かる表示にしたいと思っています。

その後は、配布版としての安定性を上げながら、Addon API周りも少しずつ広げていく予定です。
